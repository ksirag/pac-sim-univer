# Pacer Simulator

PWA-симулятор ходьбы и бега для iPhone (Safari и «На экран Домой»). Интерфейс на русском, без backend, аккаунтов и облака: все данные хранятся только на устройстве (IndexedDB).

> **Важно.** Это симулятор. Дистанция, темп и шаги рассчитываются по заданным вами параметрам; данные не берутся с датчиков и GPS и не выдаются за реальную активность. Приложение **не интегрировано** с Pacer и Apple Health и ничего туда не записывает. Калории — оценка по формуле. Работа в фоне на iOS не гарантируется: при возврате в приложение расчёт восстанавливается по часам.

## Возможности

- **Активность:** ходьба/бег, выбор сохранённого маршрута или режим без маршрута; задайте два из трёх параметров (дистанция, время, темп/скорость) — третий посчитается; длина шага или число шагов; предупреждения о нереалистичных значениях и ошибки при противоречиях; старт, пауза, продолжение, завершение; движущийся маркер на карте; итоговая карточка; повтор маршрута «по кругу» / «туда и обратно», если дистанция длиннее маршрута.
- **Маршруты:** редактор на карте (добавление, перетаскивание, удаление точек, отмена/повтор, свободное рисование, замыкание, разворот, упрощение), построение по улицам через отдельный адаптер маршрутизации с запасным вариантом (прямая линия), импорт GPX с проверкой, экспорт GPX, переименование, копия, удаление. Большие треки (до 25 МБ; более 30 000 точек упрощаются).
- **История:** список с сортировкой, статистика за неделю и месяц, график за 7 дней, подробности, удаление с подтверждением, экспорт в JSON.
- **Настройки:** вес и рост, тема, политика возврата в приложение, маршрутизация и источник карты, экспорт/импорт резервной копии с проверкой, удаление всех данных, инструкция установки на iPhone.
- **PWA:** manifest, иконки, standalone, service worker (кэш файлов приложения), сообщение об отсутствии сети. Карты **не кэшируются** и офлайн не работают.

## Стек

React 18 + TypeScript + Vite, Leaflet, Dexie (IndexedDB), `@tmcw/togeojson`, `vite-plugin-pwa`, Vitest, Playwright. Стили — собственные токены (`src/styles/tokens.css`).

## Структура

```
src/core      чистая логика: геометрия, метрики, симуляция, GPX, маршрутизация, статистика, валидация, резервные копии
src/db        Dexie-схема и репозиторий (+ запасной режим в памяти)
src/ui        компоненты, карта (Leaflet), редактор, хуки, контекст приложения
src/screens   экраны
src/styles    токены и стили
e2e           браузерные тесты Playwright
scripts       генерация иконок
public        иконки PWA, _headers для Cloudflare Pages
```

Бизнес-расчёты не зависят от анимации: время считается по меткам `Date.now()`, а состояние активности сохраняется в IndexedDB и восстанавливается после перезагрузки.

## Запуск

```bash
npm ci
npm run dev          # разработка: http://localhost:5173
npm run typecheck    # TypeScript
npm run lint         # ESLint
npm test             # unit-тесты (Vitest)
npm run build        # production-сборка в dist
npm run preview      # просмотр сборки: http://127.0.0.1:4173
npm run test:e2e     # браузерные тесты (нужен Chromium)
```

Для `test:e2e` без установленных браузеров Playwright задайте путь: `PLAYWRIGHT_CHROMIUM=/путь/к/chrome npm run test:e2e` (или выполните `npx playwright install chromium`).

## Публикация на Cloudflare Pages через GitHub

Эти шаги выполняет владелец аккаунтов (вход и права доступа — за вами):

1. Создайте пустой репозиторий на GitHub и отправьте в него проект:
   `git remote add origin <адрес репозитория>` → `git push -u origin main`.
2. В [Cloudflare Dashboard](https://dash.cloudflare.com) откройте **Workers & Pages → Create → Pages → Connect to Git** и выберите репозиторий (при первом разе GitHub попросит разрешить доступ приложению Cloudflare).
3. Настройки сборки:
   - **Framework preset:** None (или Vite)
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
   - **Node.js:** переменная окружения `NODE_VERSION` = `22`
4. Нажмите **Save and Deploy**. Адрес вида `https://<проект>.pages.dev` работает по HTTPS — это обязательное условие для service worker и установки на экран «Домой».
5. Проверьте: страница открывается, в DevTools → Application виден manifest и активный service worker, на iPhone работает «На экран Домой».

Секреты, ключи и пароли для работы приложения не нужны и в репозиторий не добавляются. Заголовки безопасности задаёт `public/_headers`.

## Установка на iPhone

1. Откройте адрес приложения в **Safari**.
2. Нажмите «Поделиться» (квадрат со стрелкой).
3. Выберите **«На экран “Домой”»** → **«Добавить»**.

Данные Safari и установленного приложения могут храниться раздельно — перенесите их через резервную копию (Настройки → Экспорт / Импорт).

## Внешние сервисы и их ограничения

- **Карта:** публичные плитки OpenStreetMap (атрибуция показана на карте). Для умеренного личного использования; для большой нагрузки укажите собственный источник плиток в настройках.
- **Построение по улицам:** публичный сервис FOSSGIS (OSRM) без гарантий и с лимитами; используется через адаптер с очередью запросов, таймаутом и предохранителем. При недоступности участок рисуется прямой линией, работа продолжается. Можно указать свой OSRM-сервер (https).
- Геолокация запрашивается только по нажатию кнопки «Показать моё местоположение» в редакторе и нигде не сохраняется.

## Известные ограничения

- Фоновая работа на iOS не гарантируется (страница может быть приостановлена); расчёт восстанавливается по часам при возврате.
- Карты не работают офлайн.
- Проверки на реальном iPhone (safe area, клавиатура, жесты) в автоматических тестах не выполнялись: тесты прогнаны в эмуляции мобильного Chromium.
- Калории — оценка по уравнениям ACSM.
